ROOT CAUSE

The R2 replacement verifier assumes that every successful replacement must
remove every occurrence of the old text:

  old_after == 0

That assumption is valid for replacements where the new text does not contain
the old text.  It is invalid for an extension replacement where the old line is
intentionally retained as the first line of a larger new block.

The manifest-field replacement is exactly that form:

  old
    disposable_vbox_post_registration_sha256

  new
    disposable_vbox_post_registration_sha256
    disposable_vbox_pre_rewrite_file_id
    disposable_vbox_post_registration_file_id

After a correct replacement, the complete new block occurs once and the old
line also occurs once inside that new block.  Therefore:

  old_after = 1
  new_after = 1

is the expected successful result for this replacement.  The same structural
condition exists for the corresponding report-field extension.

This is a wrapper verification-contract defect.  It is not a failure of the
original preparer, VirtualBox isolation, file copying, XML rewriting or VM
registration.
