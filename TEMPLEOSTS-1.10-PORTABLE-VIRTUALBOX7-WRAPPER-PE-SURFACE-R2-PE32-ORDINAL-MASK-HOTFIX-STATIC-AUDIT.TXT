OBSERVED DEFECT

PE32 branch:

  $OrdinalMask = [uint64]0x80000000

Windows PowerShell evaluates hexadecimal literal 0x80000000 as signed Int32 -2147483648 before conversion. Converting that negative Int32 to UInt64 throws InvalidCastIConvertible.

The adjacent PE32+ branch already uses UInt64.Parse with NumberStyles.HexNumber and InvariantCulture.

SURGICAL CORRECTION

The runner binds both Git tree and local working-tree source to exact failed blob f1c28ad864ad6cbf9c4465ac1e15613745f6d000.

It requires exactly one occurrence of:

  $OrdinalMask = [uint64]0x80000000

and zero pre-existing occurrences of the replacement.

It replaces only that statement with:

  $OrdinalMask = [uint64]::Parse(
      '80000000',
      [System.Globalization.NumberStyles]::HexNumber,
      [System.Globalization.CultureInfo]::InvariantCulture
  )

It then requires old count 0 and new count 1.

The patched source is reparsed with System.Management.Automation.Language.Parser before invocation. Any parse error fails closed.

EXECUTION SURFACE

The runner itself executes only Git read operations needed to bind the source blob:

- git rev-parse HEAD:<source path>
- git hash-object -- <source path>

It does not execute Portable-VirtualBox7.exe.

It does not execute VBoxManage.
It does not execute pnputil, devcon, sc, net, rundll32, driver installers, or service-control mutation.

After the in-memory correction it invokes the same R2 inspector logic with the same user-supplied PortableVirtualBoxRoot, WrapperBinaryInspectionReportPath, and OutPath.
