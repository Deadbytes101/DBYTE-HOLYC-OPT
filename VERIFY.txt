r9 native RedSea source transport
R8 showed that the R7 ISO9660/Joliet filesystem could not be traversed
from stock TempleOS 5.03. FSt_ISO9660 is marked Not Supported
by its own kernel even though the host ISO and 7z checks were valid.

R9 clones the independently SHA-256-pinned original TempleOS boot ISO
and adds a real RedSea /DBPATCH directory with four byte-pinned sources.

bitmap, an empty root directory slot, RedSea volume sector count
and two ISO volume size descriptor fields.

r10 independent RedSea image audit
tools/check_redsea.py does NOT import the RedSea builder.
It walks the actual root directory, DBPATCH directory and four source records.
All source SHA256 pins and the boot ISO identity are independent constants.
It verifies all RedSea allocation bits, including preservation of prior bits,
zero-filled unallocated appended sectors, and zero source-sector padding.
It rejects modifications to original boot/media bytes beyond explicitly
allowed RedSea and ISO volume metadata and the single unused root slot.
These checks proved three R9 verifier gaps: a modified original bitmap bit,
hidden tail data, and modified padding each previously passed audit.
Negative tests first reproduced all three false accepts; after the repair
the full pinned Windows suite passes 42/42.
The read-only check for an R9 image is:
python -m tools.check_redsea --original <pinned-TempleOS-ISO> --candidate <new-RedSea-ISO>
A host directory and SHA readback is not a guest-side file read and
cannot establish a built patched HolyC compiler or a useful optimizer.
R10 is a verifier increment based on R9, not a compiler performance release.

r11 native HolyC first IR rewrite
backend evidence at pinned TempleOS commit c26482bb6ad3f80106d28504ec5db3c6a360732c:
Compiler/BackLib.HC ICMov already skips same-register moves.
The new pass instead removes a dead 64-bit register write when the
immediately following 64-bit register move overwrites the same destination
without reading its prior value. Exact flag and type guards reject all
stack, memory, float, register conversion and pass-trace forms.
The transformation uses OptSetNOP1 before OptPass789A. It does not change
original assembler, x86-64 backend, compiler ABI, or upstream source.

r13 guest compiler build entrypoint — 2026-10-23

R12 delivered four pinned sources in /DBPATCH, but its Compiler.PRJ kept
relative includes for dozens of stock compiler files that are not in DBPATCH.
The pinned original TempleOS 5.03 boot ISO actually contains /Compiler and
/Kernel trees with compressed .HC.Z / .HH.Z file records.

R13 keeps those original trees byte-for-byte and adds GUEST.PRJ as the fifth
file in /DBPATCH. the new guest-side entrypoint maps three patched imports to
the actual /DBPATCH/CEXTS.HC, /DBPATCH/PRSLIB.HC and /DBPATCH/DBOPT.HC names.
all unchanged compiler imports point to /Compiler. existing absolute kernel
and compiler header imports stay rooted. Compiler.PRJ itself is preserved
as a pinned reference, not recommended as the guest entrypoint.

the source input and generated GUEST.PRJ are separately pinned. generator
rejects unexpected import syntax or anchor drift. independent RedSea audit
checks all five file extents, SHA256, allocations and original byte invariants.
the real ISO host test checks every GUEST.PRJ include against original RedSea
/Compiler and /Kernel directory records or the delivered /DBPATCH files.
