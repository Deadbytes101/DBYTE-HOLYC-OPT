AUTHORIZED MUTATION SURFACE

Exactly two intended Windows service-control mutations:

1. sc create VBoxSup
   binPath = exact portable app64\drivers\vboxsup\VBoxSup.sys
   type = kernel
   start = auto
   error = normal
   DisplayName = PortableVBoxSUP

2. sc start VBoxSup

This follows the observed Portable-VirtualBox upstream VBoxSup route rather than invoking the broad wrapper.

POST-CREATE GATES

Registry service object must exist and must resolve to:

  ImagePath    exact portable VBoxSup.sys
  Type         1 / kernel driver
  Start        2 / AUTO_START
  ErrorControl 1
  DisplayName  PortableVBoxSUP

POST-START GATES

- sc query must return exit 0
- numeric STATE must be 4
- CIM driver rows are recorded when available
- SYS/INF/CAT hashes must remain exact

LOCALE HARDENING

Running-state proof uses numeric sc STATE 4 only.
It does not require the localized RUNNING text token.

POWERSHELL COLLECTION HARDENING

Add-ScEvidence Lines explicitly allows empty collection and empty string entries.
This avoids the previously observed Windows PowerShell List[string] blank-row binding defect.

FAILURE SEMANTICS

If failure occurs after entering the mutation boundary:

- write one external failure report when possible
- record whether create/start succeeded
- do NOT automatically stop/delete/rollback the service
- preserve actual host state for inspection
- rethrow the failure

The script intentionally does not hide or repair a partial host mutation.

PERSISTENCE NOTE

The selected upstream-compatible service contract uses AUTO_START.
Therefore a successful create persists a VBoxSup service definition until a separately authorized cleanup removes it.
No cleanup is included in this script.
