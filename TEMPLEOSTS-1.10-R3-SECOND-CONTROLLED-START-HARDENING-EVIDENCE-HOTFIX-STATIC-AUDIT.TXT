STATIC CORRECTION 1

Base behavior:
- Write-AttemptReport captured VBoxHardening.log by Get-FileHash + Get-Content with fatal error semantics.
- a successful running VM may still hold the hardening log open.
- evidence capture failure must not be allowed to overwrite the actual start outcome.

Runner correction:
- exact Get-HardeningEvidence function cardinality 1 -> 1.
- missing log remains a normal empty observation.
- existing log hash/tail capture is wrapped in try/catch.
- capture failure returns Path + empty Hash/Tail + Error text.
- report records hardening_log_capture_error.
- no start/service/storage state is changed by this correction.

STATIC CORRECTION 2

Base behavior:
- StartIssued was set true immediately after Invoke-Native returned from startvm.

Runner correction:
- StartIssued is set true immediately before the startvm invocation.
- after the irreversible start boundary is crossed, any invocation/post-observation exception can therefore enter the failure-report route.
- this does not add another start command.
