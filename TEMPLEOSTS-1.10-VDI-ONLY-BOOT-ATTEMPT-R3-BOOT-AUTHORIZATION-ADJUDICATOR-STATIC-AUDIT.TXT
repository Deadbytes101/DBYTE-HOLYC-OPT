SNAPSHOT SEMANTICS

The adjudicator deliberately reuses the already-proven snapshot-list behavior from the original preparer:
  exit code 0 -> return captured rows
  nonzero plus exactly 'This machine does not have any snapshots' -> normalize to empty inventory
  any other nonzero result -> fail

This avoids falsely rejecting a zero-snapshot machine solely because VBoxManage represents that state with a nonzero exit code in this route.

MACHINE-READABLE SEMANTICS

The parser is aligned with the original preparer's proven ConvertFrom-VBoxMachineReadable behavior:
  split on first '='
  ignore non key/value rows
  strip optional surrounding quotes from keys and values
  decode escaped quote and escaped backslash sequences
  reject empty normalized keys
  reject duplicate normalized keys

The final implementation uses numeric character constants:
  [char]92 for backslash
  [char]34 for double quote

This removes source-level escaping ambiguity while retaining the same intended normalization semantics.
